# 从想法到代码：这个学习助手如何工作

## 四科扩展入口

现有章节学习流程继续保留。新增四科入口位于 `/academy/?local=1`，与公开版共享阅读和实验组件；课程注册表统一管理科目、路径、课时 ID 和实验，具体见 [四科说明](CORE_COURSES.md)。

新增三科仍使用既有 `StudyGuide`、SQLite 章节、笔记版本、作答、奖励和 JSON 备份约定，不重建旧数据库。原计网与微课堂接口及已发布题目位置保留。公开课程包由规范课时导出，不包含用户数据和模型配置。实验规则可独立用 Node.js 测试，浏览器记录与 SQLite 课时记录分别保存。

## 产品约定

程序围绕「正在学哪一章」组织内容，而不是让用户每次从一个空白聊天框开始。课程与教材提供上下文，章节是生成、保存、追问和练习的单位。

两种输入方式使用相同的学习内容结构，但有不同的证据要求：

- **资料模式**：按照用户提供的真实文本整理，知识点引用已有片段。
- **标题模式**：根据课程和章节主题进行通用讲解，不声称读取过某本教材。

教材名称、章节标题、学习目标和基础程度进入提示词。教材版本只有在用户填写或原文提供时才知道，程序不推断某版本的目录或页码。

## 前端负责什么

`dist/index.html` 定义页面结构与表单，`styles.css` 处理桌面、平板和手机布局，`app.js` 管理交互状态和接口调用。

前端的职责是让学习流程清楚、可恢复：

1. 选择已保存章节，或填写一个新章节。
2. 导入资料、查看提取结果、指定页码范围。
3. 展示生成状态、成功结果或错误。
4. 将结构化内容呈现为知识点、例题、类比、自测和来源。
5. 保存笔记、作答、完成标记和追问。

前端不直接请求模型服务、不保存模型密钥、不自行决定正确答案。学习记录以数据库为准；浏览器存储仅用于未提交的表单草稿和正在关注的任务编号。

当前前端使用原生 JavaScript。这个体量下不需要为了启动网页引入打包流程；如果后续增加复杂编辑器、更多页面或多人协作，可以在保持接口与数据格式的基础上迁移到 React 或 Vue。

## 后端负责什么

`backend/main.py` 提供 FastAPI 接口并托管静态网页，让前后端共用同一个本机地址。

| 功能 | 实现位置 | 关键职责 |
| --- | --- | --- |
| 文档导入 | `main.py` | 限制类型与大小，提取正文，记录空页和解析提示 |
| 来源组织 | `main.py` | 按页码取章节、拆分长片段、保留来源编号 |
| 模型适配 | `ai.py` | 统一请求格式、超时和错误处理，隐藏密钥 |
| 总结流程 | `ai.py` | 小节梳理、合并、结构化生成、格式与引用校验 |
| 数据结构 | `models.py` | 输入校验、知识点与例题等输出结构 |
| 数据持久化 | `storage.py` | SQLite 表、事务、示例初始化、历史读取 |
| 备份与恢复 | `backups.py` | 版本化学习备份、内容校验、冲突副本和导入去重 |
| 打印讲义 | `handout.py` | 将已保存的完整章节生成可打印页面，转义全部资料文字 |
| 演示内容 | `sample.py` | 独立的教学示例，不依赖模型可用性 |

## 总结流程为什么这样分

```text
章节选择
  → 从文件页序或粘贴正文取得实际文本
  → 保留每个片段的来源编号和标签
  → 短章节直接梳理；长章节分组梳理
  → 生成统一结构的知识点、例题、类比与练习
  → 校验格式、选项和来源编号
  → 成功后以一个完整章节写入数据库
```

### 1. 先确定范围，再调用模型

文件上传与章节生成是两个不同步骤。导入教材后可以查看提取文字，再选择章节起止页。

有内嵌书签的 PDF 会返回目录标题、层级和起始文件页序。结束页按下一同级或上级书签的前一页估算；目录乱序、损坏或超出处理限制时，只保留可定位的起始页。前端明确提示检查范围，选择书签后仍可修改标题与页码。这不识别印刷目录，也不保证同一页上的小节边界精确。

目录来自 pypdf 的 `outline` 与 `get_destination_page_number`，具体接口见 [PdfReader 文档](https://pypdf.readthedocs.io/en/stable/modules/PdfReader.html)。书签元数据保存在本次上传结果及浏览器草稿中；已生成章节仍以选中来源片段的数据库快照为准。

如果选中不存在的页、空白或无法提取文字的页，后端会在调用模型前报错。选中内容超过 9 万字符也会要求拆分，不会悄悄只取开头一段来代表整章。

每段实际输入都包含一个编号，如 `p12-s1`，并保留「文件名 · 文件第 12 页」这样的标签。数据库保存被选入本章的片段快照，后续换文件不会改变已有章节的依据。

### 2. 长章节先分组整理

短章节直接作为上下文。长章节按现有片段分组，逐组抽取概念、公式、条件、例题思路和易错点，并要求保留原始来源编号，再合并生成整章学习内容。

这避免一次输入太长，但中间摘要可能遗漏细节，因此不能把「已处理全部片段」理解为已经证明「总结包含全部重要知识」。内容质量仍需要用真实教材样例评审。

### 3. 要求结构化输出

`StudyGuide` 约束输出包含：

```text
overview           章节概览
objectives         学习目标
prerequisites      前置知识
knowledge_points   知识点、解释、记忆句、易错点、来源编号
worked_examples    原创例题、步骤、答案、错误提醒
analogies          场景、对应关系、类比局限
quiz               四选一自测、正确选项序号、解析
```

统一结构让前端能单独展示每个知识点、逐题检查答案、将来源跳转到原文片段，而不是处理一个不可拆分的长文章。

### 4. 检查后才保存

后端检查必需字段、合理的数量和长度、四个不重复的选项、正确选项索引范围，以及每个来源编号是否真实存在。学习目标、解题步骤和类比对应关系等列表中的每一项也必须包含非空文字，不能用只有空格的条目通过检查。资料模式的知识点不能没有来源；标题模式不能虚构来源。

结构或来源编号检查失败时，程序将错误反馈给同一个模型，要求重写一次。如果仍不合格，则任务失败，不保存部分结果。

这些是**结构与引用完整性检查**。它们不验证逻辑推导、数值运算或引用是否真正支持结论。后续提升内容可靠性时，应优先建设真实章节评审集和可复算题目的专项校验，而不是只增加提示词长度。

## 追问与整章总结不同

整章总结需要覆盖选定范围。追问通常只需要少量相关原文，因此当前实现使用简单的关键词匹配选择同章片段，再附上章节内容和最近几轮对话。

中文关键词采用相邻且重叠的双字组合，避免固定切分位置漏掉词语；英文数字词按完整词匹配，不把 TCP 当作 tcpip 的内部子串命中。每个资料片段只做一次大小写规范化，按得分排序后选入最多 18000 字符的来源文字。它仍是简单的词面检索，不保证理解同义表达或找到所有相关依据。

这个实现没有向量数据库，也没有联网检索。它适合一个章节内的问答；如果后续需要跨多本书查资料，再增加关键词全文索引、语义检索或混合检索。检索结果仍然需要保留来源。

## 打印是章节快照

打印入口先保存笔记，再打开 `/api/chapters/{id}/print`。后端从数据库生成整章 HTML，用户和模型文字全部转义；样式与交互在独立的 `handout.css`、`handout.js` 中，继续使用应用的内容安全策略。打印页面不会调用模型，也不依赖原网页当前打开的是哪个标签页。

自测题与答案用分页样式分开；答案、笔记和来源附录可选择是否打印。PDF 由浏览器的打印功能生成，后端没有额外的 PDF 服务依赖。讲义保留打开时的内容，用户后续改笔记时需要重新打开。

## 数据库保存什么

| 表 | 保存内容 |
| --- | --- |
| `materials` | 文件名、按页提取的文字、解析提示 |
| `chapters` | 课程、教材、标题、来源模式、学习内容、来源快照、笔记和完成状态 |
| `jobs` | 生成任务状态、当前阶段、错误和生成的章节 ID |
| `attempts` | 每章每道题的最新作答和判定 |
| `messages` | 章节追问、回答与时间 |
| `backup_imports` | 已处理备份记录的来源 ID、内容摘要和对应本机章节，防止重复导入 |

生成成功时，章节写入和任务完成状态在同一事务中提交。重启后，尚未完成的任务会标记为中断，避免永远显示生成中；不会自动重放可能产生费用的模型请求。

数据库使用 SQLite WAL 模式。运行时的数据库、密钥和浏览器测试结果均在版本控制忽略范围内。

笔记还有独立的版本号。前端保存时带上读到的版本，后端只在版本仍一致时更新；如果另一窗口已经保存过，返回冲突提示。前端保留当前输入，允许把最新的另一份笔记合并后保存，避免无声覆盖。

## 复习和备份怎样复用已有数据

错题复习从每题的最新作答中选择错误项，通过同一个作答接口检查和保存，因此和原章节使用一致的答案与结果。复习列表在提交前不返回正确答案和解析。它没有另外虚构一套“掌握度”，也没有将未答题算成错题。

JSON 备份采用带版本号的固定结构，只导出学习记录。数据库读取在一个一致的快照中完成，避免导出到一半时混入不同时间的笔记和作答。模型配置和密钥由另一个文件管理，未进入备份字段。

导入先完整校验整份文件，包括知识点来源编号、题目索引和作答判定的一致性，再在一个写事务中合并。已有章节保留；发生内容冲突时分配新 ID 并加上「导入副本」名称。已处理的来源 ID 与内容摘要记录到 `backup_imports`，即使导入响应丢失，重试也不会重复创建同一批副本。导入过程的数据库错误会使整个事务回滚。

## 可以怎样继续发展

有真实使用反馈后，再按问题扩展：

- 教材范围常选错：在现有 PDF 书签选章基础上，增加印刷目录识别与更精细的章节边界确认。
- 公式识别不准：增加专门的公式 OCR 与渲染。
- 生成题计算错误：对地址划分、传输时延等明确题型实现确定性计算检查。
- 记不住知识：用作答历史设计错题复习与间隔复习，而不是仅统计打开次数。
- 多教材追问困难：增加可评估的检索流程和跨教材引用。

这些是后续方向，不是本版已经实现的能力。

## 前端加载与记录规模

章节读取和模型设置读取分别推进，模型设置的延迟不再阻挡离线阅读。晚到的初始化设置通过修订号检查，避免覆盖用户刚读取或保存的设置。章节加载失败保留当前内容并提供重试；已取消的导航不再展示旧请求错误。

学习列表每页 50 条、错题列表每页 10 条，仍属于浏览器渲染分页。问答则使用服务端分页：`GET /api/chapters/{id}/study` 在一致快照内读取章节和最近 30 条问答，`GET /api/chapters/{id}/messages?before=消息ID` 按固定游标读取更早记录。新增问答不影响旧记录的边界，前端按消息 ID 去重并忽略属于其他章节的迟到响应。旧章节详情接口与 JSON 备份保留完整问答。前端遇到旧服务尚未重启、没有新接口时可退回原接口。

展开旧对话时保持当前滚动位置，加载失败保留记录及游标以便重试。保存笔记、答题和标记完成不读取聊天历史；AI 追问只读取使用到的最近 4 条问答。错题页使用全局题目索引保留作答草稿。

新章节草稿使用 300 毫秒防抖合并浏览器存储写入。明确的文件变更、提交和关窗保存仍及时执行；正常离开页面与切至后台也尝试补存。这类浏览器草稿不等同于 SQLite 中已经保存的章节、笔记或问答。

作答中的状态按章节 ID 和题号保存在共享集合中，而不是只依赖某个按钮的 disabled 属性。自测与错题复习共同检查这份状态，所以 DOM 重绘、切换标签和关闭复习窗口不会提前解锁同一道题。请求结束后释放状态；选项变更和键盘焦点在题目重绘后保留。

## 编辑意图与后台完成状态

原题选项按章节和题号维护编辑修订号。复习请求记录提交时的修订号，响应到达时只清理未再次编辑的旧选项。复习列表重绘后恢复当前选项的焦点，避免正在操作另一题时被异步响应打断。

模型设置读取合并重复打开操作，已打开的表单不会再次填入旧数据。保存请求保留提交快照；等待期间不同的新密钥不会被旧响应清空，表单修订号用于显示仍有未保存修改的提示。

生成任务收到完成状态后，转换为可再次点击的打开入口，而非把后续的页面读取失败当成任务仍在执行。自动打开前核对导航修订号，保留用户刚作出的章节选择。首页记录的上次阅读位置只作为浏览器端偏好，不参与学习备份或覆盖明确的章节链接。

## 内置计算机网络课程

`backend/network_course.py` 定义原创课程内容与目录。课程元数据和进度通过 `GET /api/course/network` 返回；`POST /api/course/network/lessons/{id}/open` 用固定版本 ID 和 `INSERT OR IGNORE` 按需创建课时记录。不会在启动时批量填满用户的章节列表，不会在再次打开或升级启动时覆盖已保存笔记、题目和作答。综合卷使用同一机制，两个固定版本 ID 分别选取交错的 12 个课时。

课时复用 `StudyGuide`、现有作答、错题、笔记冲突控制、打印与备份契约，来源明确标识为原创讲义。v1 内容若进行影响题序或答案的更新，应使用新版本 ID 或明确迁移，不应直接替换已有记录的题目并保留旧题号结果。

`dist/course.js` 提供目录、状态筛选、前后课导航和计算实验，不引入前端依赖。打开课时先读取/创建章节，再使用现有 `openChapter` 完成笔记保存与切换。课程目录按需读取，不阻塞原有首页加载。切换失败保留原页，计算实验用输入修订号隔离过时结果。

`backend/network_labs.py` 使用标准库 `ipaddress`、浮点时延计算和有界比特序列异或除法，不调用模型或系统网络命令。服务端校验输入范围、非有限数与多项式格式；客户端字段约束只作为交互辅助。

## 学习奖励与阅读流畅度

`learning_rewards` 使用唯一事件键，课题首次答对奖励和课时全对奖励均通过 `INSERT OR IGNORE` 防重。奖励与作答写入处于同一 SQLite 事务内，失败会一同回滚；并发重试不会重复发放。只对固定课程 ID 且题目内容匹配的课时发奖，综合卷和任意导入副本不重复计分。`learning_days` 以本机日期和题目键联合去重，用于当天复习量，不发额外积分。

成长等级和徽章根据已获得奖励计算，错误重答不撤销已得积分。JSON 备份第 2 版加入奖励账本与每日练习记录；第 1 版仍可导入。奖励事件必须符合固定课程、类型和分值，每日记录按日期与题目键去重；章节、奖励和每日记录在同一事务内合并，任一写入失败都会回滚。纯成长记录恢复也允许导入，重试不会重复加分。

每日练习推荐先选当前答错的题，再选尚未领取首次奖励的题，按课程顺序稳定排序；当天已正确作答的题会跳过，除非之后又答错。推荐只查询固定课程的作答和讲义，避免遍历用户全部章节。界面在答题、章节切换、回到窗口及导入备份后更新成长信息，不持续后台轮询。

`rewards.js` 在章节显示后独立读取，不阻塞首章加载；答题后短暂合并刷新，不进行后台轮询。课程目录合并在途读取，章节写入后再读取最新目录；同一动画帧内的连续搜索输入合并为一次 DOM 重绘。专注选择使用会话存储，读取失败时保持普通模式，不修改学习数据。


## 微课堂与课程注册表

`microclass_supplements.py` 提供原创进阶知识点、迁移例题和闭卷自查；构造时深拷贝初版讲义，避免缓存重建重复追加。`microclass_revisions.py` 冻结初次发布的讲义及题目指纹。仅匹配完整原版 guide/sources 指纹的内置课时可以更新，使用条件 UPDATE 防止覆盖并发修改；仅更新 guide/sources，不写笔记、版本号、作答、问答、进度或积分。启动、内置课时打开、备份导入后触发检查。导入的修改版或冲突副本不自动替换。后续版本若需更新本次增强版，必须新增已发布版本的明确指纹，不能从修改后的内容重算旧指纹。

`microclass.py` 提供独立 12 节课程；`curriculum.py` 合并两套课程的规范题目，仅用于奖励校验和推荐，不改变原目录顺序或综合卷选题。新版目录接口为 `/api/course/microclass`，打开接口为 `/api/course/microclass/lessons/{lesson_id}/open`。存储仍用既有章节、作答、笔记和奖励表，不迁移或覆盖旧课。

目录缓存和在途请求按课程分别维护；阅读中的前后节导航依据当前章节所属课程，不能被另一个目录的选择改变。新推荐附带 `course_id`，前端按规范章节前缀路由到对应打开接口。奖励条目上限由注册表题数与课数求和，当前为 228；原课程徽章只统计原课程奖励键。
