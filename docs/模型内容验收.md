# 接通真实模型后，怎样检查总结质量

程序测试只能证明导入、生成接口、校验、保存和阅读流程按预期运行。真正的知识质量，需要对照明确的输入和参考答案检查。本目录的验收记录不会把本地测试替身当作真实模型评测。

## 固定材料，再比较结果

`examples/` 中增加了三份原创小节材料，可分别上传为 Markdown 文件，使用「根据我的资料」模式。它们适合快速发现问题，不能代表整本教材，也不能代替复杂公式或图表样本。

| 材料 | 要覆盖的重点 | 本项目练习的核对值 | 常见失败表现 |
| --- | --- | --- | --- |
| PPP 成帧与透明传输 | 边界、字节转义、差错检测各自的作用 | 指定载荷转义后为 6 字节，可逆回 4 字节 | 混用字节和比特填充；把检测说成自动纠错 |
| TCP 序号与窗口 | 字节编号、累计确认、接收与拥塞窗口 | 确认 1300；缺口未补仍是 1300；可新增 600 字节 | 每个报文只加 1；越过缺口确认；忽略在途数据 |
| DNS 查询与缓存 | 递归与迭代的角色、TTL 单位、题目条件 | 35 秒时剩 85 秒；121 秒按题设已过期 | 混淆两种角色或 TTL；把教学条件说成普遍规则 |

协议依据链接放在各份材料中；算式与数值练习为本项目编写。先核对材料本身，再核对生成结果。模型不需要逐字复制材料里的例题，也不保证一定生成这些相同数值；如果它新编了题目，要重新计算新题的答案。

## 一次检查的操作

1. 记录模型服务、模型名称、检查日期、输入文件、学习目标和基础程度。不要在记录中写 API 密钥。
2. 对同一份材料生成一次，导出 Markdown 留存。需要比较模型或提示词时，保持其余条件一致。
3. 逐个知识点打开来源，检查引用是否真正支持结论，而不只是编号存在。
4. 独立复算所有例题与自测；逐一检查四个选项，不能只验证正确选项看起来合理。
5. 检查类比是否有清晰对应关系、是否说明局限，有没有引入新的误解。
6. 记录漏掉的小节、错误陈述、错误计算和引用不支持的具体位置。修正后重新检查，不用整体印象替代证据。

如果再用另一模型辅助审查，应保留它给出的具体依据；两次模型回答一致，也不能单独证明正确。

## 可复制的记录模板

```text
日期：
模型服务与模型名称（不含密钥）：
材料文件与版本：
生成设置：
导出文件位置：

覆盖：哪些小节已覆盖，哪些遗漏？
定义与条件：哪句话准确或有误？对应原文是什么？
来源：逐项核对后，哪些引用不支持结论？
例题：逐题复算结果，必要的适用条件是否写出？
自测：每题是否只有一个正确答案，解析是否一致？
类比：对应关系与局限是否清楚？
额外内容：资料外的补充是否有标识？

需要修正的问题：
复查结果：
检查人：
```
