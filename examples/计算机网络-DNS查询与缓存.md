# DNS 查询与缓存

这是本项目编写的小节练习材料，非教材原文。它用于比较概念解释与带条件的计算，不是完整 DNS 教程。

## 本节知识

递归查询把继续寻找答案的工作交给提供递归服务的一方。迭代解析过程中，查询方根据收到的转介继续询问其他服务器；一次非递归响应也可能直接给出答案，不一定都是转介。不要把递归理解成「客户端亲自问遍所有服务器」。这些角色与行为可核对 [RFC 1034](https://www.rfc-editor.org/rfc/rfc1034.html) 第 4.3 节。

缓存可以复用先前获得的结果。TTL 使用秒作为单位，影响记录的缓存有效时间；它不是网络层 IP 分组的跳数限制。DNS 资源记录格式见 [RFC 1035](https://www.rfc-editor.org/rfc/rfc1035.html) 第 3.2.1 节。

本节按普通缓存过期模型计算，明确不考虑预取、刷新、记录变更和过期数据服务。实际实现可能依据 [RFC 8767](https://www.rfc-editor.org/rfc/rfc8767.html) 在无法刷新等规定条件下提供过期数据，因此不能把本题条件说成所有实现的绝对规则。

## 原创练习

某记录在 t = 0 秒进入缓存，当时剩余 TTL 为 120 秒，之后没有刷新。t = 35 秒时还剩 85 秒；t = 121 秒时，按本题的普通过期模型，不能继续把旧记录视作有效缓存直接使用。

## 生活类比及边界

向服务台询问办事地点，由服务台替你继续联系各部门，类似递归服务；别人告诉你下一处可以询问的位置，你自己继续找，类似迭代过程。实际 DNS 使用机器可处理的名称、记录和消息，这个类比不代表所有服务器都提供递归，也不代表每次都要从同一个起点查起。
